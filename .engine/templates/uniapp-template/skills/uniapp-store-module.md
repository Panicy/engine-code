# Skill: uniapp-store-module

## 任务边界

用于新增或调整 Pinia store，例如业务角色、工作区信息、列表筛选状态、登录态扩展，并保证缓存和清理策略明确。

适合：

- 跨页面共享状态。
- 登录态、权限态、工作区态。
- 需要本地缓存的业务状态。

不适合：

- 单页面临时 UI 状态。
- 复杂页面布局实现。
- 后端接口封装。

## 开始前先看

1. `store/workspace.js`：业务状态、getter、actions、缓存示例。
2. `store/auth.js`：登录态示例。
3. `utils/cache.js`：缓存读写和清理方式。
4. `store/pinia.js`：Pinia 初始化入口。
5. 相关 API 函数：确认状态来源。

## 本地实现惯例

- Store 使用 Pinia。
- `state` 存数据，`getters` 做派生判断，`actions` 做状态变化。
- 需要持久化时统一使用 `utils/cache.js`。
- 提供便捷导出函数，便于 API 或工具函数访问 store。
- 退出登录、角色变化、工作区切换、401/403 时要有清理策略。

## 实现步骤

1. 判断状态是否需要跨页面共享或持久化。
2. 定义 `state`、`getters`、`actions`。
3. 需要缓存时定义明确 cache key。
4. 实现 hydrate、set、clear 等生命周期动作。
5. 提供便捷导出函数。
6. 接入调用方。
7. 运行 `npm test`。

## 不要做

- 不要把复杂 UI 逻辑塞进 store。
- 不要重复维护同一业务状态。
- 不要直接在多个页面操作同一缓存 key。
- 不要遗漏退出登录或无权限时的清理策略。

## 跨端对齐

- Store 字段和后端返回字段保持语义一致。
- 401/403 后不能残留错误权限态。
- 页面展示只消费 store，不重复造状态。

## 自查清单

- 状态单一来源清楚。
- getters 不产生副作用。
- actions 负责状态变化和持久化。
- 有缓存就有清理策略。
- 401/403 场景下状态不会残留错误权限。

## 何时停止猜测

- 状态生命周期、缓存策略或权限清理策略不明确。
- 同一状态已经存在多个来源，需要先确认重构范围。
