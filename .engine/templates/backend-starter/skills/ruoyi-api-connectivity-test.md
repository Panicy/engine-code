# Skill: ruoyi-api-connectivity-test

## 任务边界

用于验证后台接口真实连通性、菜单权限数据、鉴权边界和 404 行为。它是测试型 skill，服务于已实现的后台功能或接口变更。

适合：

- 新增接口后的连通性测试。
- 后台菜单和按钮权限写入后的验证。
- 排查 401、403、404。
- 为 Review Runner 或人工验收提供测试证据。

不适合：

- 新增业务代码，这类使用 `ruoyi-module-crud`。
- 编写数据库结构，这类使用 `ruoyi-database-migration`。
- 长期关闭鉴权来让测试通过。
- 在没有本地运行环境时伪造接口结果。

## 开始前先看

1. `backend-starter/docs/api-connectivity-testing.md`：接口连通性测试约定。
2. `backend-api.json`：接口路径、方法、参数、响应。
3. `permission-manifest.json`：权限码、菜单、按钮权限。
4. `bootstrap-state.json`：确认基座数据库和 Redis 已初始化。
5. `application-dev.yml` 或本地运行参数：确认后端地址和鉴权方式。

## 本地实现惯例

- 先测试错误路径，再测试未登录，再测试合法鉴权请求。
- 未登录访问受保护接口返回 401、403 或框架未授权响应都可以，但不能当作业务成功。
- 正确接口路径不能返回 404。
- 菜单和按钮权限必须能从 `sys_menu` 查询到。
- 临时关闭鉴权只能用于隔离接口本身是否可用，最终必须恢复。
- 测试证据只记录响应摘要，不记录 token、密码、cookie 等敏感信息。

## 实现步骤

1. 读取 `backend-api.json`，列出本次要验证的接口。
2. 读取 `permission-manifest.json`，列出菜单和按钮权限。
3. 检查 `bootstrap-state.json` 是否完成；未完成时停止并说明需要先初始化基座。
4. 启动或确认后台服务正在运行。
5. 对不存在的相邻路径发起请求，验证 404 或框架约定错误。
6. 未登录访问受保护接口，验证 401/403 边界。
7. 使用合法鉴权访问接口，验证状态码、响应结构、分页字段、错误语义。
8. 查询 `sys_menu`，验证菜单和权限码已写入。
9. 如临时调整鉴权配置，恢复后再次检查 diff。
10. 输出测试结果摘要，记录命令、结果、失败原因和建议。

## 不要做

- 不要把 401/403 失败误判成接口不可用。
- 不要把 404 用 mock 跳过。
- 不要把临时 `@SaIgnore`、放行路径或测试账号硬编码留在代码里。
- 不要在测试证据中保存 token、cookie、密码。
- 不要为了通过测试扩大权限范围。
- 不要在未初始化基座数据库时继续测业务接口。

## 跨端对齐

- 后台接口路径要和中台、客户端 API 封装一致。
- 权限码要和 `sys_menu.perms`、后端注解、中台按钮权限一致。
- 401/403 行为要能被中台和客户端统一请求层识别。
- 分页参数和响应字段要能被中台表格消费。

## 自查清单

- `backend-api.json` 中的正确路径没有 404。
- 错误路径能暴露 404 或框架约定错误。
- 未登录请求能暴露 401/403 或未授权响应。
- 合法鉴权请求能返回业务响应。
- `sys_menu` 中能查到新增菜单和按钮权限。
- 临时鉴权修改已恢复。
- 测试结果没有泄露敏感信息。

## 何时停止猜测

- 后台无法启动，且日志不足以判断原因。
- 没有合法测试账号或 token 获取方式。
- 基座数据库未初始化。
- 权限码、菜单父级或接口契约不明确。
- 需要修改安全配置才能继续，但用户没有确认。
