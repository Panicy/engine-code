# Skill: ruoyi-api-change

## 任务边界

用于修改已有后端接口、服务逻辑、查询条件、返回字段或权限控制。

适合：

- 已有 API 的小范围行为调整。
- 查询条件、返回字段、权限控制变化。
- Bug fix 或局部重构。

不适合：

- 新增完整 CRUD 模块，这类优先使用 `ruoyi-module-crud`。
- 同时改中台页面或客户端页面。
- 大范围重构登录、鉴权、租户、数据权限。

## 开始前先看

1. 受影响 Controller：确认 URL、HTTP 方法、权限注解和返回结构。
2. 受影响 Service/ServiceImpl：确认业务逻辑位置。
3. 受影响 Mapper/XML：确认查询字段、条件和返回映射。
4. 中台或客户端 API 调用：确认是否已有下游依赖。
5. `backend-starter/docs/api-connectivity-testing.md`：确认接口变更后的连通性测试。

## 本地实现惯例

- 尽量保持 API 路径、HTTP 方法、响应包结构兼容。
- 查询条件变化要同步 Bo、Mapper wrapper、XML。
- 返回字段变化要同步 Vo、Mapper 查询和下游类型定义。
- 权限变化要同步 `@SaCheckPermission`、菜单按钮 SQL、中台 `v-access:code`。
- 业务判断放 Service，Controller 不堆复杂逻辑。

## 实现步骤

1. 定位现有 Controller、Service、Mapper、Bo、Vo。
2. 查找中台或客户端是否已有对应调用。
3. 根据 task 修改接口行为、查询条件、返回字段或权限。
4. 同步必要 SQL、字典、菜单权限。
5. 建议更新 API 契约、权限清单和连通性测试记录。
6. 运行编译和接口连通性检查。

## 不要做

- 不要静默改变已有 API 路径或 HTTP 方法。
- 不要移除鉴权来规避 401/403。
- 不要只改后端而不记录中台/客户端影响。
- 不要让 Vo 字段和中台类型长期不一致。

## 跨端对齐

- 如果接口字段变化，中台 `model.d.ts` 和客户端展示字段需要同步。
- 如果权限码变化，中台按钮权限和菜单 SQL 需要同步。
- 如果接口路径变化，所有 API client 都需要同步。

## 自查清单

- 变更接口正确路径不返回 404。
- 错误路径不会误命中。
- 未登录访问受保护接口仍返回 401/403 或框架未授权响应。
- API 返回结构仍符合 `R<T>` 或 `TableDataInfo<T>`。
- 下游影响已在任务结果或后续任务中说明。

## 何时停止猜测

- 变更会破坏中台/客户端兼容，但 task 未覆盖下游。
- 权限策略变化没有 PRD 或 task 明确说明。
- 需要新增第三方依赖或改变鉴权配置。
