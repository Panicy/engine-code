# Skill: ruoyi-database-migration

## 任务边界

用于新增或调整业务功能的表、字段、索引、初始化数据、菜单和按钮权限 SQL。它只处理业务增量，不负责后台基座初始化。

适合：

- 创建业务表。
- 调整字段或索引。
- 新增字典数据。
- 新增菜单和按钮权限。

不适合：

- 导入 RuoYi 基础库、默认用户角色菜单、系统字典，这类使用 `ruoyi-base-bootstrap`。
- 完整 CRUD 代码实现，这类使用 `ruoyi-module-crud`。
- 存量数据复杂迁移但缺少迁移策略。
- 引入 job/workflow 相关 SQL，除非任务明确要求。

## 开始前先看

1. `backend-starter/docs/database-conventions.md`：表字段、菜单权限、字典约定。
2. `backend-starter/docs/database-baseline.md`：基础表和初始字典。
3. `backend-starter/docs/new-feature-database-design.md`：新功能建表决策清单。
4. `script/sql/ry_vue_5.X.sql`：基础 SQL 样式和菜单权限写法。
5. `bootstrap-state.json`：确认基础库已经初始化。

## 本地实现惯例

- 项目业务表 SQL 放在项目扩展 SQL，不改 `ry_vue_5.X.sql`。
- 如果 `bootstrap-state.json` 不存在或不是 `ready`，先停止并提示需要基座初始化。
- SQL 顺序为基础 SQL、业务表 SQL、菜单权限 SQL。
- 新功能优先先判断表类型：主表、关联表、明细表、日志表、配置表。
- 常见审计字段包括 `create_dept/create_by/create_time/update_by/update_time/remark`。
- 逻辑删除字段通常是 `del_flag`，是否需要必须由业务决定。
- `sys_menu.menu_type` 中 `M` 为目录、`C` 为菜单、`F` 为按钮。
- 字典由 `sys_dict_type` 和 `sys_dict_data` 组成。
- 系统配置优先判断是否应使用 `sys_config`，密钥和环境值不要写入通用 SQL。

## 表设计决策清单

开始写 SQL 前先确认：

- 这是主表、关联表、明细表、日志表还是配置表？
- 是否已有基础表可以复用？
- 是否需要唯一约束？
- 是否需要状态字段、排序字段、备注字段？
- 是否需要审计字段？
- 是否需要逻辑删除？
- 是否需要部门、数据权限或租户字段？
- 是否需要初始化数据？
- 是否需要菜单和按钮权限？
- 是否需要字典或系统配置？
- 是否涉及存量数据迁移和回滚？

## 实现步骤

1. 确认 SQL 是初始化脚本还是增量脚本。
2. 检查 `bootstrap-state.json`，确认基础库已初始化。
3. 用表设计决策清单确认建模边界。
4. 确认表名、字段类型、默认值、是否允许空、索引、备注。
5. 判断是否需要审计字段、逻辑删除、部门、租户或数据权限字段。
6. 编写业务表 SQL。
7. 需要菜单时补充 `sys_menu` SQL，并和后端权限标识一致。
8. 需要字典时补充 `sys_dict_type` 和 `sys_dict_data`。
9. 涉及存量数据迁移时写清楚回滚和兼容策略。
10. 建议同步记录数据库变更清单和权限清单。

## 不要做

- 不要覆盖 starter 基础 SQL。
- 不要把业务表写入 `ry_vue_5.X.sql`。
- 不要在业务迁移中导入后台基础库。
- 不要写入其他项目的环境配置或密钥。
- 不要使用 `test_demo/test_tree` 作为正式业务表。
- 不要在未确认时默认加入租户字段或逻辑删除字段。
- 不要机械给每个字段都加索引。
- 不要把强业务结构塞进 `sys_config` 逃避建表。

## 跨端对齐

- SQL 字段要和后端 Entity、Bo、Vo、Mapper XML 对齐。
- 菜单权限 SQL 要和后端 `@SaCheckPermission`、中台 `v-access:code` 对齐。
- 字典值要和中台/客户端展示组件对齐。

## 自查清单

- 表名、字段名、索引、备注符合约定。
- 基座初始化状态为 `ready`，或已明确标记需要先初始化。
- 表类型判断清楚。
- 主键、唯一约束和高频查询索引有明确理由。
- 审计字段和逻辑删除策略明确。
- 部门、数据权限、租户字段有业务依据。
- 菜单父级、排序、按钮权限明确。
- 字典类型和值没有与已有字典冲突。
- 存量迁移风险已记录。
- SQL 可执行，应用启动不会因 Mapper 字段不一致失败。
- 新增接口正确路径不返回 404，未登录访问受保护接口返回 401/403 或框架未授权响应。
- 新增菜单和按钮权限能被查询到。

## 何时停止猜测

- 字段含义、迁移策略、菜单父级、租户策略、逻辑删除策略不明确。
- 需要变更基础表或基础 SQL。
- 需要处理生产存量数据但没有回滚要求。
- 无法判断应使用业务表、字典还是 `sys_config`。
